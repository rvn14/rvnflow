# 0.2 stability investigation

Baseline: origin/main f06b11f (0.1.0). Existing CI passes, so the missing coverage is runtime behavior.

## Confirmed findings

- `Engine::update` holds `data` across mutation closures, disk sync, event emission,
  alarms and notifications. `window_set_mode` and `settings_update` call `window::apply`
  from these closures. Native move/focus callbacks synchronously lock the same mutex.
  This creates a lock inversion when a worker waits for a UI window call while the UI
  waits for state. Native getters/setters must never run under this lock.
- Timer/task/settings commands are synchronous Tauri commands. Tauri executes these
  on the UI thread; JSON read/write and sync operations therefore block input processing.
- Startup loads, validates and rewrites storage synchronously and uses a blocking error
  dialog. Focus loss also writes a full save on the UI thread.
- `Timer::complete` intentionally leaves `Completed/00:00`; only `start` selects `next`.
  This explains the reported transition behavior directly.
- `skipTaskbar: true` and the absence of a minimize command make taskbar minimization unavailable.
- Sound preview calls settings Save, unexpectedly persisting unrelated draft changes.
- Task row actions expand horizontally on hover and consume title width. The short task
  viewport and persistent input need explicit layout regression tests with 50 tasks.

## Reproduction and repairs

An isolated detached worktree of f06b11f was instrumented to call the original resize
transaction on a worker, using a separate app identifier and a temporary data directory.
It wrote `entered original resize transaction`, never wrote completion, did not exit
within 12 seconds, and Windows reported `Responding: False`. Only that test process
was terminated. The original transaction holds the state lock while a native window
getter waits on the UI thread, whose move/focus callbacks are waiting for the same lock.
This is a reproduced native lock inversion, not an inference from a screenshot.

The repaired repository serializes writers separately from short-lived snapshot locks.
It releases data locks before mutation callbacks, save I/O and publication; OS effects
run after transactions. Tauri commands execute off the UI thread. Window event handlers
queue persistence/native work. Asynchronous startup provides loading and recovery states;
no blocking recovery dialog is used. Diagnostic logs rotate at 256 KiB plus one backup,
with fixed codes and no task contents.

Rust now atomically records completion, increments focus credits once, selects the next
session and optionally auto-starts from the current wake time. Defaults require manual
start. Break/focus automation is independent. Foreground feedback uses a single in-app
toast, while background notifications use contextual Windows titles and configured durations.
Schema 1 migrates safely to 2; explicit old preferences and user tasks are preserved.

Minimize, collapse, tray hide and Quit are distinct native actions. Restore unminimizes
the existing window. The expanded widget is 350 × 560 logical pixels. Task controls and
the composer stay outside the scrolling rows; More actions no longer squeeze row text.
Sound previews use draft values without saving preferences.

## Executed verification

- Rust integration tests cover transactions, slow saves/reentrant reads, concurrent writes,
  persistence failures, migration, timer cycles, independent automation, sleep anchoring,
  contextual notification content and bounded logs.
- Vitest covers timer/task interactions, preview-without-saving, event cleanup/reconnection,
  stale and duplicate completion events, formatting and progress boundaries.
- Browser tests cover 0, 1, 10 and 50 tasks at 100%, 125%, 150% and 200% scale, editing,
  Enter-to-add, failed saves retaining text, composer bounds and startup recovery.
- `scripts/test-native.ps1` passed first launch and saved running-session restart using
  isolated debug builds. Each run verified frontend IPC readiness, compact/expanded sizes,
  running timer continuity while minimized/hidden, taskbar restore, tray restore,
  exactly-once history, automatic ready-break selection and second-instance activation.

The native computer-use helper remains unavailable. Programmatic window tests ran
against real Windows/WebView2, but visible notification delivery in an installed app,
audible output, physical DPI transitions, and multi-monitor interactions remain manual.
No new GitHub Actions run or installed-app acceptance is claimed for this local branch.

Build the versioned installer with `pnpm tauri build --bundles nsis`:
`src-tauri/target/release/bundle/nsis/RVNFlow_0.2.0_x64-setup.exe`.

No push or release publication is part of this repair run.
